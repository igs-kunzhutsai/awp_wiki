# decisions/ — 為什麼這樣設計

**架構決策記錄。** 選了什麼、拒絕了哪些替代方案、當時的取捨是什麼。

| | |
|---|---|
| **放** | 決策背景、候選方案、選擇理由、被拒絕方案的問題、已知代價 |
| **不放** | 怎麼做（→ `flow/`）、規範本身（→ `conventions/`） |

## 為什麼要記

決策的理由**不會過期**（`WIKI-SPEC.md` 規則 5），但會被遺忘。
沒記下來的話，半年後有人會提出一個當初已經評估過並否決的方案。

每頁應包含：決策日期、當時的處境、考慮過哪些方案、為什麼選這個、接受了什麼代價。

## 命名

`why-c-style-api.md`、`state-machine-objectified.md` —— 用結論或主題命名，不用日期。

> 本檔只說明「這個目錄放什麼」，不列出頁面清單（`WIKI-SPEC.md` §2）。
