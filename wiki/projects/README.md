# projects/ — 各專案特有

**一個專案一個資料夾。** 只放「換一個專案就不成立」的知識。

| | |
|---|---|
| **放** | 該專案的設定值、bet / denom 表、特殊需求、只有它踩過的雷 |
| **不放** | 換個專案還成立的知識（→ 共用區 `modules/` `flow/` …）、跨專案的地區規則（→ `regions/`） |

## 🔴 地區是欄位，不是資料夾

同一個專案會有多個地區版本。**不要開 `projects/<專案>/<地區>/`。**

那會變成笛卡爾積：新增一個地區要開 N 個資料夾，每個 90% 內容相同，
改共同部分要改 N 份。地區差異多半是「同一件事的不同值」，寫成表格一列一地區即可。

```markdown
| 地區 | denom | max bet | JP 上限 |
|---|---|---|---|
| 菲律賓 | 1 / 5 / 25 | 500 | 有 |
| 澳門 | 5 / 10 | 1000 | 無 |
```

新增地區 = **加一列**。

## 每個專案資料夾的結構

```
projects/<專案名>/
├── setup.md    設定、bet / denom 表（地區差異用表格欄位）
└── issues.md   只有這個專案踩過的雷
```

專案小的時候兩頁就夠。長到十幾頁再考慮給它自己的入口頁 —— 那時候是特例不是通則。
